# Reconstruction Workflow

Use this reference when a raster reference image is provided and the output must be an editable `.drawio`.

## Analyze the Image

Create a reconstruction table before editing files.

```text
Canvas: [width] x [height]
Global layout: [flowchart | teaser | dashboard | comparison grid]
Panels:
- id=A, bbox=(x,y,w,h), title=..., role=..., method=drawio|svg-tile|hybrid
- id=B, bbox=(x,y,w,h), title=..., role=..., method=drawio|svg-tile|hybrid
Rows/columns:
- row1: y=..., h=..., repeated elements=...
- col1: x=..., w=..., repeated elements=...
Assets:
- tile name, bbox, source script, output path
Draw.io-native elements:
- text, boxes, separators, simple arrows, legend text
```

## Identify the Figure Type

### Flowchart

Signals:

- One dominant reading direction.
- Stage numbers or stage titles.
- Repeated lanes.
- A central mechanism panel.
- Objective or loss/output area at the end.

Reconstruct as:

- One canvas-level grid.
- Stage headers and separators in draw.io.
- Repeated lane groups generated by loops.
- Detailed blocks as SVG tiles.
- Legend as draw.io text plus small SVG swatches.

### Teaser

Signals:

- Multiple labeled panels.
- Concept overview, mechanism explanation, and evidence side by side.
- Mixture of icons, Venn/overlap diagrams, small plots, and bar charts.
- More narrative structure than a pure pipeline.

Reconstruct as:

- Panel-level grid first.
- Each panel gets its own local grid.
- Plot-heavy cells become SVG tiles.
- Panel badges, titles, row labels, column headers, and legends stay editable in draw.io.

## Redraw, Do Not Trace

Do not copy every pixel. Preserve:

- Relative composition.
- Repeated structure.
- Semantic labels.
- Color roles.
- Direction and hierarchy.
- Evidence shown by plots or schematic distributions.

Do not preserve:

- Raster artifacts.
- Accidental spacing.
- Low-quality generated text.
- Decorative shadows or glows.
- Unexplained irregularities that make later editing harder.

## Work Order

1. Read the reference image dimensions.
2. Decide canvas size. Use the same aspect ratio unless the user asks otherwise.
3. Draw a panel/grid map with exact pixel boxes.
4. List every tile needed. Name tiles by panel, row, column, and purpose.
5. Implement tile scripts.
6. Run tile scripts and check generated SVG dimensions.
7. Implement the draw.io composer.
8. Embed SVG tiles with data URIs.
9. Add editable text and draw.io-native geometry.
10. Run the composer and inspect the `.drawio` XML.
11. Export a preview if tooling is available.

## Quality Bar

The result should be easier to edit than the reference image:

- Text can be selected and edited in draw.io.
- Stage and panel spacing can be changed numerically.
- Repeated components are generated consistently.
- Dense visual content is isolated in replaceable SVG tiles.
- The final file does not depend on external image paths unless explicitly requested.
